 基于科大讯飞虚拟人能力封装的纯 JS SDK，不挑框架。本文档以「先跑通、再扩展」为原则组织：先看 **第 6 章「五分钟最小接入」** 即可驱动起虚拟人，其余章节按需查阅。

## **1. 文档说明**
### **1.1 SDK 简介**
虚拟人 SDK 将讯飞的形象渲染、语音合成（tts）、语音识别（asr）、语义理解（nlp）、自动动作（air）等能力融合封装，提供一套统一的 JS API，帮助你快速接入虚拟人交互场景。SDK 纯 JS 实现，可在任意前端框架（Vue / React / 原生）中使用。

### **1.2 适用场景**
+ PC 端、大屏、Web 应用中的虚拟人播报、问答、客服、导览等。
+ 文本驱动（让虚拟人说指定内容）与智能交互（接入大模型问答）。

## **3. 浏览器与部署环境**
### **3.1 浏览器兼容性**
推荐 Chrome / Edge 等现代浏览器。SDK 依赖 WebRTC、MediaDevices、H.264 解码等能力。

### **3.2 HTTPS 和安全上下文**
麦克风录音、媒体设备调用要求 **安全上下文**：`https://` 或 `http://localhost`。非安全域名下 `navigator.mediaDevices` 为 `undefined`，无法录音。

### **3.3 麦克风权限**
首次录音浏览器会请求麦克风权限。`startRecord` **必须在用户与页面发生交互后**调用，否则因浏览器安全策略被拒绝。

### **3.4 自动播放限制**
浏览器禁止未经用户交互的页面自动播放声音。若 start 后画面有但无声音 / 口型动而无声，会收到 `PlayerEvents.playNotAllowed`：需引导用户点击页面，再调用 `player.resume()` 恢复带声音播放。

### **3.5 跨域和 CSP**
连接走 WSS；如有 CSP 策略，需放行接口域名的 `connect-src`。

### **3.6 PC、移动端和小程序支持**
- **PC / 大屏**：推荐场景，兼容性最佳。

- **移动端 / Android 浏览器**：不保证全部支持（设备内核差异大），不建议 Android/iOS 套壳 H5。

- **小程序**：建议改用 web-api，`protocol` 用 `rtmp`，拿到地址后用 `live-player` 拉流。

## **6. 五分钟最小接入**
仅保留必要参数与必要流程。先用 `protocol / avatar_id / vcn` 跑通，再按需加参数。

**调用流程：** 创建实例 → 监听事件 → `setApiInfo` → `setGlobalParams` → `start` → `writeText` 驱动 → `stop`。

```plain
import AvatarPlatform, { SDKEvents, PlayerEvents } from './sdk/.../index.js'

// 1) 创建实例（默认使用内置播放器）
const avatar = new AvatarPlatform()

// 2) 注册必要事件
avatar
  .on(SDKEvents.connected, () => console.log('连接成功'))
  .on(SDKEvents.error, (e) => console.error('error', e?.code, e?.message))
  .on(SDKEvents.disconnected, (e) => e && console.error('异常断开', e))

// 处理浏览器自动播放限制
const player = avatar.player || avatar.createPlayer()
player.on(PlayerEvents.playNotAllowed, () => {
  // 引导用户点击页面后恢复声音
  document.addEventListener('click', () => avatar.player?.resume(), { once: true })
})

// 3) 设置接口信息（四项必填）
avatar.setApiInfo({
  serverUrl: 'wss://avatar.cn-huadong-1.xf-yun.com/v1/interact',
  appId: 'xxx',
  apiKey: 'xxx',
  apiSecret: 'xxx',
  sceneId: 'xxx', // 接口服务ID
})

// 4) 设置全局参数（仅必要项）
avatar.setGlobalParams({
  stream: { protocol: 'xrtc' },                       // 实时视频协议
  avatar: { avatar_id: 'xxx', width: 720, height: 1280 }, // 已授权形象 + 分辨率(4 的倍数)
  tts: { vcn: 'xxx' },                                // 已授权发音人
})

// 5) 启动并拉流到指定容器（容器必须有宽高）
await avatar.start({ wrapper: document.querySelector('.wrapper') })

// 6) 文本驱动 / 交互
await avatar.writeText('你好，我是虚拟人', { nlp: false }) // 纯播报
await avatar.writeText('你是谁？', { nlp: true })          // 经大模型回答（需开通大模型）

// 7) 断开（务必调用，释放路数）
avatar.stop()
// 销毁实例（组件卸载时）
avatar.destroy()
```

渲染容器 `.wrapper` 必须具备大小，画面以 `contain` 模式填充，不会自动撑开。

各步骤的完整参数见 [第 11 章 参数参考](#11-参数参考) 与 [第 15 章 API 完整参考](#15-api-完整参考)。

## **7. 生命周期和状态管理**
### **7.1 实例状态**
`new` → 设置阶段（`setApiInfo` / `setGlobalParams`，须在 `start` 前）→ `start` 连接拉流 → 交互中 → `stop`（可重连）/ `destroy`（不可复用）。

### **7.2 连接流程**
`start()` 内部：发起连接 → `connected` → 初始化 → 获取流地址 → 拉流 → 播放成功 → `resolve`。失败则 `reject`，连接或拉流任一阶段出错均会终止会话。

### **7.3 页面隐藏和恢复**
页面切到后台可能影响心跳与渲染。恢复可见后如渲染异常，调用 `player.resize()` 刷新。

### **7.4 网络断开**
被动断开触发 `SDKEvents.disconnected`，回调含 `error` 时说明因异常断开。

### **7.5 重连策略**
`stop()` 后实例仍可复用：可修改参数后再次 `start()` 重连。需自行实现重连退避逻辑。

### **7.6 组件卸载时释放资源**
Vue / React 组件卸载时调用 `stop()` 或 `destroy()`，避免占用路数与设备资源。

⚠️ 实例不要挂在会被框架代理（如 Vue `reactive` / `ref`）的对象上，否则可能报 `Cannot read private member`。挂全局或普通变量即可。

## **8. 播放器**
### **8.1 创建播放器**
默认 `useInlinePlayer: true`，无需手动创建。取实例：`const player = avatar.player || avatar.createPlayer()`。

### **8.2 设置容器**
通过 `start({ wrapper })` 指定渲染容器；容器尺寸变化后调用 `player.resize()`。

### **8.3 / 8.4 XRTC / WebRTC 播放**
`stream.protocol` 选 `xrtc`（支持透明背景，需 `alpha:1`）或 `webrtc`。`rtmp` 不支持 SDK 内播放（用于小程序等场景）。

### **8.5 自动播放恢复**
收到 `PlayerEvents.playNotAllowed` 后，引导用户点击页面再调用 `player.resume()`。

### **8.6 音量和输出设备**
```plain
player.muted = true            // 静音 / 解除静音
player.volume = 0.5            // 音量 [0~1]
await player.setSinkId(deviceId) // 切换输出设备
```

### **8.7 PlayerEvents**
| 事件 | 说明 |
| :--- | :--- |
| `play` | 开始播放 |
| `waiting` | 数据缓冲等待 |
| `playing` | 缓冲后继续播放 |
| `not-allowed`（`playNotAllowed`） | 浏览器禁止自动播放 |
| `error` | 播放错误（如 `700002` 设备不支持 H.264） |


## **9. 录音器**
> ⚠️ 使用内置录音（全双工 / 短语音）期间，****勿手动调用 `writeAudio` / `writeText`****。

### **9.1 创建录音器**
SDK 默认不创建，需手动：`const recorder = avatar.recorder || avatar.createRecorder({ sampleRate: 16000 })`。交互拾音固定 `16000`。

### **9.2 短语音录音**
`duration > 0`：最长录音 `duration` 毫秒后自动停止（类似微信按住说话）。

```plain
recorder.startRecord(60 * 1000, () => console.log('录音结束'), { nlp: true })
```

### **9.3 全双工录音**
`duration = 0`：持续聆听，实时识别与交互，直至 `stopRecord()`。

```plain
recorder.startRecord(0, () => console.log('已停止'), { nlp: true })
```

### **9.4 停止录音**
`recorder.stopRecord()`。虚拟人会理解 `startRecord` 至 `stopRecord` 间的音频并回答。

### **9.5 切换输入设备**
`await recorder.switchDevice(deviceId)`。

### **9.6 RecorderEvents**
| 事件 | 说明 |
| :--- | :--- |
| `mute` / `unmute` | 麦克风静音 / 解除 |
| `error` | 录音异常（设备移除、权限关闭等） |


## **10. 核心功能**
### **10.1 文本驱动**
`writeText(text, { nlp: false })`：原样播报文本（含标点 < 2000 字），不经理解。

### **10.2 文本交互**
`writeText(text, { nlp: true })`：文本经大模型理解后回答（需开启「大模型对话」）。

### **10.3 音频驱动**
`writeAudio(buffer, status, extend)`：手动写入 16k 16bit 单通道 PCM。首帧 `status=0`、中间帧 `1`、末帧 `2`。常规场景请用录音器，非特殊流程勿手动调用。

### **10.4 短语音交互**
见 [9.2](#92-短语音录音)，单轮按住说话式交互。

### **10.5 全双工交互**
见 [9.3](#93-全双工录音)，实时连续交互。

### **10.6 打断**
`interrupt()`：丢弃未播报内容，同时打断语音播报与语义返回。

### **10.7 动作驱动**
+ `writeCmd('action', 'A_Hello_l_F')`：立即触发动作（标签到「接口服务 - 形象列表 - 查看动作」获取）。
+ 文本内嵌：`writeText('大家好[[action=A_RH_hello_O]]我是数字人')`。

3D（卡通）形象播报中发动作会打断当前播报；2D（真人）形象无此问题。

### **10.8 自动动作**
`setGlobalParams({ air: { air: 1, add_nonsemantic: 1 } })`：按语境自动匹配动作（需形象支持动作）。

### **10.9 流式文本**
`writeText` 支持流式发送，需 **追加模式**（`interactive_mode: 0`）。务必按标点拼成整句再发，勿逐字 / 发空文本，否则卡顿或报错。

### **10.10 字幕**
`setGlobalParams({ subtitle: { subtitle: 1, font_color: '#fff' } })`：2D 形象支持；透明背景 / 3D 形象不支持。也可监听 `nlp` 事件自行展示文本。

### **10.11 背景图片**
`setGlobalParams({ background: { type: 'url' | 'res_key', data } })`。

### **10.12 透明背景**
`stream.protocol: 'xrtc'` + `stream.alpha: 1`。超拟人形象不支持透明背景。

## **11. 参数参考**
### **11.1`setApiInfo(apiInfo)`**
| 参数 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `serverUrl` | string | ✅ | 接口地址 |
| `appId` | string | ✅ | 应用 AppId |

### **11.2`setGlobalParams(config)`**
接入建议：先只传必填项调通，再按需增加。

**stream（视频流，必填）**

| 参数 | 必填 | 说明 |
| :--- | :--- | :--- |
| `protocol` | ✅ | `xrtc` / `webrtc` / `rtmp`（仅 xrtc 支持透明背景） |
| `alpha` | — | 透明背景 0 关 1 开，需配合 xrtc |
| `bitrate` | — | 码率，默认 1000000 |
| `fps` | — | 帧率 0–25，默认 25 |


**avatar（形象，必填）**

| 参数 | 必填 | 说明 |
| :--- | :--- | :--- |
| `avatar_id` | ✅ | 已授权形象 ID |
| width/height | — | 视频分辨率（**必须为 4 的倍数**），非画布尺寸 |
| `mask_region`  | — | 裁剪 `[左,上,右,下]`，超拟人不支持 |
| `scale`  | — |  缩放 0.1–1 |
| `move_h`  / `move_v` | — | 左右 / 上下移动，[-4096, 4096] |
| `audio_format`  | — | 音频采样率，1=16k 2=24k |




**tts（发音人，必填）**

| 参数 | 必填 | 说明 |
| :--- | :--- | :--- |
| `vcn` | ✅ | 已授权发音人 |
| `speed` / `pitch` / `volume` | — | 语速 / 语调 / 音量 |


**其他（均非必填）**

| 节点 | 说明 |
| :--- | :--- |
| `avatar_dispatch.interactive_mode` | 0 追加 / 1 打断 |

## **12. SDKEvents**
通过实例 `on` / `off` 注册（须在 `start` 前）。

| 事件 | 参数 | 说明 |
| :--- | :--- | :--- |
| `connected` | `InitResponse` | 连接建立 & 链路初始化完毕 |
| `disconnected` | `error?` | 被动断开；含 `error` 即异常断开 |
| `stream_start` | — | 引擎侧首帧推流开始（不代表端侧已出画面） |
| `frame_start` / `frame_stop` | `WsResponse` | 单次交互推流起 / 止帧（≈开始/结束说话） |
| `action_start` / `action_stop` | `WsResponse` | 单次动作推流起 / 止帧 |
| `tts_duration` | `WsResponse` | 单次推流预计总时长 |
| `asr` | `WsResponse` | 语音识别结果 |
| `nlp` | `WsResponse` | 语义理解结果 |
| `subtitle_info` | `WsResponse` | 字幕信息 |
| `error` | `(code, message, data?)` | 错误事件 |


```plain
interface InitResponse {
```

## **17. 安全接入**
### **17.1 浏览器不得保存 apiSecret**
生产环境严禁在前端明文存放 `apiKey` / `apiSecret`。

### **17.2 服务端生成 signedUrl**
推荐：`setApiInfo` 仅传 `appId`、`sceneId`、`signedUrl`，其余不传。`signedUrl` 由后端鉴权后返回完整地址：

```plain
wss://avatar.cn-huadong-1.xf-yun.com/v1/interact?authorization=xxx&host=avatar.cn-huadong-1.xf-yun.com&date=xxx
```

鉴权方式参考 Web API 文档握手部分。

### **17.3 CSP 和日志脱敏**
放行接口域名的 `connect-src`；日志中对密钥、签名脱敏。

## **18. 性能和弱网处理**
+ 分辨率传 1080P（1920×1080）即可，过大影响清晰度与带宽。
+ 弱网下适当降低 `bitrate` / `fps`。
+ 心跳超时（`10114 over time`）多为网络问题。
+ 流式播报按标点拼整句再发，避免逐字驱动导致卡顿。
